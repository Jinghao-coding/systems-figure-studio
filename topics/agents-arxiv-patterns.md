# Agent / Multi-agent · 已保留的画法

这些构造来自 v0.4.1 的历史整理；方向选择记录不代表具体成图已验收。按当前文稿的对象、关系和视觉要求选用。

## AP01 · 角色 Agent / role agent

**参考与状态：** AG01、AG06；改编/提案，未生成。

使用同一套简洁角色头像，旁侧放短角色名；头像下可附一条小能力带，至多展开与当前内容有关的工具、模型或人工输入。可采用机器人或其他统一角色家族，不混搭写实人像与扁平头像。沿真实任务关系排列，焦点角色略加强调。

**避免误读：** 头像只标识逻辑角色，不代表该角色拥有独立 GPU 或独立模型副本。

## AP02 · 对话与消息 / conversation, message

**参考与状态：** AG01；改编/提案，未生成。

把参与者头像固定在对话两侧，交错摆放短消息气泡；消息包含少量内容线或短片段，执行返回用更窄的结果带区别。仅展示解释机制所需的几轮，后续用留白或省略标记折叠。

**避免误读：** 同一参与者跨轮保持身份；对话轮次不自动表示并行执行。

## AP03 · 层级委派 / planner, delegation, handoff

**参考与状态：** AG01、AG06；改编/提案，未生成。

主协调者位于上方或左侧，子角色按实际职责分组。任务沿分支下发，结果用独立回传路径汇总；只展开一个子角色的工具小件，其余保持头像和短标签。留白分隔角色层与工具层，不用满屏嵌套容器。

**避免误读：** 不要预设中心协调器；仅在确有层级委派时使用。

## AP04 · Agent 局部图与群体拓扑 / agent graph, swarm

**参考与状态：** AG02、AG04；改编/提案，未生成。

每个 Agent 用一个紧凑操作小图表示：操作节点少而可辨，节点之间保留局部依赖。在小图角落放角色标识，多张小图通过边界外的消息线连接；只展开焦点角色，其余折叠成小轮廓。背景保持干净，消除彩虹贯穿箭头和重复 Logo。

**避免误读：** 区分操作节点、Agent 和模型实例三层；为通信边与内部依赖边规定清楚语义。

## AP05 · 工具调用与执行产物 / browser, terminal, artifact

**参考与状态：** AG03；改编/提案，未生成。

角色旁保留文件、浏览器或终端小图标；工具下放一张具有少量真实内容的产物片，如几行代码、一个网页局部或测试结果。沿步骤编号排列，重复角色保留同一名称，关注的是内容与交接而非 UI 装饰。

**避免误读：** 未提供真实内容时标为示意，不伪造运行记录；工具不必都变为独立 Agent。

## AP06 · 评审与修订 / review, revise, verifier

**参考与状态：** AG04；改编/提案，未生成。

用少量圆形操作节点形成“生成—评审—修订”的紧凑路径；通过条件节点把通过结果送往出口，未通过结果沿外侧弧线回到修改处。历史状态使用小记录片贴在相关位置。并行候选时用扇入的汇总结构替代串行回路。

**避免误读：** 这里只是候选构造，实际有没有反馈、循环和条件由当前机制决定；有循环的图不标成 DAG。

## AP07 · Agent 训练闭环 / rollout, trainer, model update

**参考与状态：** AG05；改编/提案，未生成。

将 Agent 执行侧与训练侧左右分开，上方路径传送短轨迹带，下方返回带版本标识的模型结构或参数薄片；Agent 一侧可含同风格工具图标。两条路径在线型或标签上可区分，去掉占据中心的大型品牌标识。

**避免误读：** 轨迹、奖励、参数更新是不同对象；不要把用于执行的 Agent 图标视为所有训练组件。

## AP08 · 工作区与运行边界 / workspace, runtime, event stream

**参考与状态：** AG07（仅语义参考，外形为补充设计）；改编/提案，未生成。

按进程或容器的真实归属放置 Agent 执行路径和工具；工作区显示文件页束，边界接口处使用小型调用记录，事件沿窄带返回。保留少量边界框，不把每个软件包再画成相同卡片。

**避免误读：** 软件包的依赖与部署进程不同；沙箱是隔离边界，不保证所有执行都必须沙箱化。

## AP09 · Agent—LLM 请求—设备映射 / serving mapping

**参考与状态：** 原创补充，待专门参考；改编/提案，未生成。

上方排逻辑角色与任务关系，中间抽出实际 LLM 调用请求条，随后映射到带 ID 的模型实例，下方是设备资源。多角色可引用同一实例；同一任务的多次调用保持调用 ID。只展开一个焦点路径，其余弱化。

**避免误读：** 角色数、请求数、实例数、GPU 数分别表示；不能仅凭头像数量推断资源占用。
