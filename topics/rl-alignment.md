## 模型角色

**词条 ID：** `model-roles`  
**词汇与别名：** target、draft、teacher、student、Actor、Critic、Reward Model、Reference Model  
**含义：** 同族模型承担不同职责；按实际算法选择角色。

### 两套独立模型体＋候选树

draft 与 target 各自有层次结构和独立边界；前者连接候选token树，后者连接验证输出；共享内容需显式引用。

### 按功能排列的模型局部

Actor 输出轨迹带，Reward 模型输出标量，Reference 输出分布；三者形体同族但内部/端口体现职责。

**参考与取舍：** [AG05](../references/sourcebook.md#ag05)、[S05](../references/sourcebook.md#s05)。借鉴所列来源的局部形体或组织关系；各候选是改编描述，不表示每种画法都直接出现在原图。

**必要边界：** 这是组合提案，未声称出自已审 SpecInfer 或 RL 原图；模型大小用示意或给定数值。

## 强化学习与对齐

**词条 ID：** `rl`  
**词汇与别名：** RLHF、RLAIF、PPO、GRPO、DPO、rollout、trajectory、policy、reward、advantage、经验缓冲区  
**含义：** 采样、评估与策略改进的总入口。

### 轨迹带与反馈环

状态/动作/奖励组成短轨迹带，采样产生轨迹，评估给出逐步或终局分数，更新路径回到明确策略版本。

### 分离的模型角色与数据流

按算法中真实存在的角色选择 Actor、Reference、Reward、Critic 等模型。模型轮廓同族，token、分布和分数分别采用序列、概率形态与标量；不为齐全而自动补满所有角色。

**参考与取舍：** [S05](../references/sourcebook.md#s05)、[AG05](../references/sourcebook.md#ag05)。从已审角色数据流中借组织方法；只呈现当前算法真实使用的角色。

**必要边界：** PPO/GRPO/DPO 流程不能混合；这是待补专门原图的提案。

## Rollout、评分与策略更新

**词条 ID：** `rl-rollout-train`  
**词汇与别名：** rollout、PPO、GRPO、actor、critic、reference、reward model、RLHF  
**含义：** 强化学习执行、数据准备与训练阶段。

### 角色节点与三段数据流

用不同角色的模型小结构组织采样、评分和训练，轨迹用有 token 次序的长带，分数为短记录。按实际算法添加 Critic、Reference 或 Reward，不预设每个算法都拥有全部模型。

### 逻辑角色到设备执行

左侧角色数据流使用圆节点，中间列简短放置对应，右侧将相同角色放入设备泳道。保留身份颜色，但以文字补充；同设备顺序执行与不同设备并行可以直接比较。

**参考与取舍：** [S05](../references/sourcebook.md#s05)。借鉴逻辑数据流—放置—执行的三层对应，减少多层虚线边框和代码块。

**必要边界：** PPO、GRPO 和其他 RL 过程不能画成同一套固定四模型图；Actor 的生成和训练可共享权重身份。

**状态：** 绘图描述可用；改编示例图未生成。具体构图、数量与外观按本次研究内容核对。

## 异步采样与策略版本

**词条 ID：** `policy-version`  
**词汇与别名：** policy version、staleness、async rollout、weight synchronization  
**含义：** 轨迹来源版本、训练版本和权重发布之间的关系。

### 版本接力与轨迹包

策略更新沿一条版本轨道向前，采样器在另一条轨道上输出带来源版本的轨迹包；包进入训练时仍保留原版本。权重发布用独立方向，不把轨迹到达误当成权重已更新。

### 并发采样器与接收窗口

多个 sampler 并排，使用的策略版本写在各自模型旁；训练端用接收窗口标明可接受版本范围。丢弃、重加权或等待仅在方案有依据时显示。

**参考与取舍：** [S05](../references/sourcebook.md#s05)。所列来源仅为相关机制或局部组织依据，具体画面由本条重新构造。

**必要边界：** 异步不天然意味着任意过期样本都可用；版本一致性与允许陈旧程度需由算法给出。

## 奖励、优势与样本掩码

**词条 ID：** `reward-advantage-mask`  
**词汇与别名：** reward、advantage、mask、log probability、credit assignment  
**含义：** 轨迹中不同监督信号与有效位置。

### 对齐的 token 与信号轨道

同一序列下方对齐放奖励、优势和 mask 三条窄轨道，最后结果奖励与逐 token 信号用不同跨度标记。只有需要解释的位置展开，其他部分折叠。

### 轨迹分组与组内比较

同一 prompt 的多个结果作为一组并列，旁侧保留其评分，在组内计算处输出各样本对应的权重或优势。组间留白，不把所有 prompt 混成一个比较集合。

**参考与取舍：** [S05](../references/sourcebook.md#s05)。所列来源仅为相关机制或局部组织依据，具体画面由本条重新构造。

**必要边界：** 奖励不等于优势；结果级与 token 级监督区别明确，不编造 credit assignment 算法。

## SFT 与偏好优化

**词条 ID：** `sft-dpo`  
**词汇与别名：** SFT、DPO、preference pair、chosen rejected、监督微调  
**含义：** 监督样本或偏好对进入优化的方式。

### 示例对与标签区间

prompt 与示范回复连续排在一条 token 带上，监督 mask 标出参与损失的位置，模型预测与标签在比较节点对齐。无需添加环境交互或奖励模型图标。

### 共享 prompt 与偏好双路

一个 prompt 分出 chosen 与 rejected 两条回复带，进入策略评估；需要 reference 时画为旁侧独立分支。比较结果进入偏好损失，不把偏好对画成正负奖励数值。

**参考与取舍：** 尚无专门原图。原创或通用构造候选；没有已绑定的专门原图。

**必要边界：** DPO 与在线 RL 训练不等同；样本、参考策略和损失细节按实际实现。
