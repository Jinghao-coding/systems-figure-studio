## 内存、显存与缓冲区

**词条 ID：** `memory`  
**词汇与别名：** 显存、memory、HBM、DRAM、SRAM、register、共享内存、寄存器、buffer、memory pool  
**含义：** 内存层次、数据驻留与可用容量。

### 层次金字塔＋实际数据块

使用层次轮廓区分快慢存储，旁边另画一个被搬移的 tile；不把金字塔面积用于精确容量。

### 切开的内存条带

长内存面按已占用/缓存/空闲切段，拉出一个块显示 token 或张量片；轮廓保持连续地址空间含义。

### 逻辑/物理双视图

左侧紧凑逻辑页，中间少量映射记录，右侧不连续物理页；用弧线逐块连接，空页保留。

**参考与取舍：** [R19](../references/sourcebook.md#r19)、[R22](../references/sourcebook.md#r22)、[S09](../references/sourcebook.md#s09)。借鉴所列来源的局部形体或组织关系；各候选是改编描述，不表示每种画法都直接出现在原图。

**必要边界：** 明确地址、容量和状态；cached 不自动等于 free。

## 数据集与存储

**词条 ID：** `storage`  
**词汇与别名：** SSD、对象存储、dataset、数据集、文件、分区、shard、dataloader  
**含义：** 数据对象、持久存储和层次归属。

### 数据页束与局部索引

不同内容的小数据页错位成束；边缘可见页序，前方抽出一页，内部以样本缩略片表示实际内容。

### 分层存储与对象搬移

上层缓存薄片、中层主存条、下层持久对象页束；同一对象沿跨层路径移动，源端按 copy/move 正确保留。

**必要边界：** 存储页与模型参数页不得不加说明地混用；避免数据库圆柱代替全部内容。

## 主机—设备传输与缓冲

**词条 ID：** `host-device-buffer`  
**词汇与别名：** H2D、D2H、pinned memory、DMA、异步拷贝、buffer  
**含义：** 从主机数据到设备可用数据的转移过程。

### 主机页束与设备薄片

主机侧用页束，设备侧用张量薄片；中间保留传输带，带内只有一个焦点批次。固定页内存区域用外括号与短标签识别，完成点之后才把设备数据标为可用。

### 计算与拷贝双泳道

共享时间轴上分开拷贝与计算两条轨道。同一批次的搬移先完成，再由细依赖线接计算；下一批次搬移可与当前计算重叠。只高亮一个依赖对，避免把所有区间连成网。

**参考与取舍：** [S02](../references/sourcebook.md#s02)。所列来源仅为相关机制或局部组织依据，具体画面由本条重新构造。

**必要边界：** 异步提交不等于数据已经可用；重叠能力和同步位置由实现决定。

## 预取与双缓冲

**词条 ID：** `prefetch-double-buffer`  
**词汇与别名：** prefetch、double buffering、ping pong buffer、数据供给  
**含义：** 通过缓冲切换组织生产与消费。

### 两个固定缓冲槽交替

A、B 两个槽位固定在画面上，分别接生产端和消费端；用两个相邻时刻展示它们交换职责。批次 ID 跟随数据，槽位 ID 不动，正在使用与正在填充可用边框和标签共同区分。

### 队列水位与前瞻窗口

用短有序队列表现已备数据，在读取指针前画一段轻括号表示预取窗口。侧面只展开当前 batch 和下一 batch 的准备路径，已消费数据从队尾真正移出。

## 数据分片与缓存局部性

**词条 ID：** `dataset-locality`  
**词汇与别名：** dataset shard、data locality、数据缓存、数据集、object storage  
**含义：** 任务、数据分片与本地缓存的对应。

### 分片页束与就近引用

将数据集画成带连续分片 ID 的页束，每个节点旁保留已有的少量分片。任务引用线只指向需要的数据；命中路径在节点内闭合，未命中路径延伸到远端存储。

### 目录与实体两层

上方放紧凑分片目录，下方放分布式存储位置；目录项通过引用连到实体分片。迁移前后使用同一 ID，复制时明确保留两份，移动时移除原位置的有效标记。

**必要边界：** 数据引用不是实际复制；副本、分片和版本分别标识。

## Embedding 查找与缓存

**词条 ID：** `embedding-cache`  
**词汇与别名：** embedding lookup、embedding table、cache miss、cache hit、稀疏特征  
**含义：** 稀疏 ID 如何取得嵌入向量，以及未命中怎样回填。

### ID 梳齿与表行抽取

左侧几枚类别 ID 像梳齿一样对齐到中间表的被选中行，右侧抽出相应向量带。未选中行只留淡轮廓，重复 ID 引用同一行而非复制整张表。

### 近端小表与远端长表

前景显示小型缓存表，后方用较长表的局部表示完整存储；命中从近端直接返回，未命中沿另一条路径访问远端并回填。用一个具体 ID 贯穿，不用对勾代替实际返回向量。

## 虚拟映射与分配器状态

**词条 ID：** `virtual-physical-memory`  
**词汇与别名：** virtual memory、physical memory、allocator、page table、fragmentation、VMM  
**含义：** 地址空间、物理存储和分配器可用状态的区别。

### 连续地址带与离散页

上方连续地址带保留稳定偏移，下方物理页按真实分配顺序排列，中间只连当前关注的几项映射。预留地址采用淡底，已映射部分用更清楚的填充；空物理页保留轮廓。

### 固定布局的连续快照

用三个同坐标快照表现请求结束、缓存保留、真正回收；结束只改变请求标记，实际释放后才清空可用槽。再次使用同一物理页时画新请求 ID，并保留页 ID。

**参考与取舍：** [S09](../references/sourcebook.md#s09)。借鉴 vAttention 的固定双层映射和连续快照，减少高对比网格，保留空白含义。

**必要边界：** 逻辑释放、缓存驻留、可驱逐、解除映射和物理回收不能合并为一个“free”。

## 本地、共享与云存储

**词条 ID：** `storage-services`  
**词汇与别名：** 本地存储、SSD、NVMe、块存储、block storage、共享文件系统、file storage、对象存储、object storage、bucket、PV、PVC、挂载、存储服务  
**含义：** 存储位于哪里、以什么接口访问，以及存储对象与实际数据的关系。

### 本地盘与共享存储池

本地 SSD 使用节点边界内的扁平盘片或盘盒；共享存储用节点外、共享范围内的紧凑盘组／服务轮廓，多个真实客户端各连访问端口。只展开一个盘或一个数据分片，其余弱化。共享池不要随节点重复复制；外部服务放在正确的集群外或平台范围内。

### 存储服务身份与内容剖面

块存储可用卷体加少量连续块，文件存储可用目录页束，对象存储可用存储桶轮廓加少量带 key 的对象片。圆柱、磁盘或 bucket 图标可直接用于身份；需要解释内容时再展开局部。数据集、模型权重和 checkpoint 用内容标签或局部数据片区分，不为每一种内容发明一套品牌 Logo。

### 声明绑定与实际读写分层

需要解释 K8s 持久卷时，上方用规格页表示 PVC 和 PV，以细映射线表示声明与绑定；下方是实际卷或后端存储。Pod 内的挂载点或块设备入口通过访问路径连后端，不让每次读写沿 PVC→PV→控制器串行经过。控制管理与数据访问在位置和标签上区分；卷类型、访问方式按部署确定。

**参考与取舍：** [C03](../references/sourcebook.md#c03)。PVC/PV 与存储后端关系核对官方文本；存储形体为原创候选，不是从该文档原图提取。

**必要边界：** 本地／远端描述位置，块／文件／对象描述访问抽象，不能混为同一个分类轴。PV/PVC 不是硬盘实物；多客户端连线不自动保证多写者模式，对象存储也不默认具有原生文件挂载语义。

**状态：** 原创／改编绘图描述可用；未生成图片。新增官方来源仅核文本，不宣称已审其图面或已获用户视觉认可。
