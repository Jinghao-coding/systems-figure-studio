## 控制器与协调循环

**词条 ID：** `controller-reconcile`  
**词汇与别名：** controller、reconcile、desired state、observed state、Kubernetes  
**含义：** 期望状态、实际状态与控制动作之间的闭环。

### 双状态页与修正回路

期望状态是一张稳定规格页，实际状态是一张带时间标记的观测页；两者进入小比较节点，动作沿弧线指向受控资源，资源变化返回新的观测。用一条主闭环，不把每个状态都套大框。

### 事件触发与幂等动作

事件条进入工作队列，取出的对象 key 引出一次调和；调和从状态源读取最新信息，再决定动作。重试沿外侧返回队列，执行历史留在短记录带，不形成无限装饰回路。

**参考与取舍：** [S11](../references/sourcebook.md#s11)。官方文档支持控制语义；双状态页和回路是原创构造。

**必要边界：** 控制器持续趋近期望状态，不等于事务中同步完成全部动作；watch 是变化通知而非直接执行。

## Watch、缓存与工作队列

**词条 ID：** `watch-workqueue`  
**词汇与别名：** watch、informer、workqueue、CRD、event stream、object key  
**含义：** 对象变更怎样触发控制器工作。

### 事件条与去重队列

资源变更以带 key 的短事件条进入缓存与队列，重复 key 通过汇合表示去重；控制器从队列取 key，再读当前对象。事件条、对象状态页和排队 key 使用不同形态。

### 共享状态与独立消费者

状态存储位于中间，多个控制器各有短工作队列；通知线只到订阅者，读取线返回共享状态。展开一个消费者，其余用同风格小节点折叠。

**参考与取舍：** [S11](../references/sourcebook.md#s11)。所列来源仅为相关机制或局部组织依据，具体画面由本条重新构造。

**必要边界：** 事件不必等于完整对象快照，也不保证每次中间状态逐一执行；具体缓存一致性依实现。

## 设备插件、运行时与驱动

**词条 ID：** `device-runtime-driver`  
**词汇与别名：** device plugin、driver、runtime、CUDA、ROCm、device allocation  
**含义：** 资源发现、授权分配与设备执行接口。

### 软件层与明确端口

应用调用、用户态运行时、驱动与设备采用分层基线，层间只画实际 API 边；设备插件位于资源管理侧，独立连接资源发现与分配，不强行插进所有 kernel 的执行路径。

### 分配链与执行链分开

左侧资源管理流决定哪个容器能看到设备，右侧容器内程序通过运行时和驱动提交计算。两链在分配结果与可访问设备处关联，用一处展开连接避免混成单条流程。

**参考与取舍：** [S11](../references/sourcebook.md#s11)、[S12](../references/sourcebook.md#s12)。官方文档用于职责和 API 语义；双链布局是本次原创构造。

**必要边界：** 设备插件一般不是计算内核转发器；厂商 API 和隔离能力需核实具体版本。

## 进程、线程与隔离边界

**词条 ID：** `process-isolation`  
**词汇与别名：** process、thread、namespace、cgroup、sandbox、container、VM  
**含义：** 执行实体、可见资源与限制范围。

### 进程边界与线程路径

一个进程边界中放多条线程细轨道，共享内存片在轨道之间；其他进程使用独立边界，IPC 穿过明确端口。线程与进程的重复粒度区别明显。

共享主机资源位于底层，上方容器边界显示各自可见对象；配额用独立标尺贴在边界旁。可用一个小锁提示隔离，但具体哪些资源隔离仍通过结构和标签说明。

## RPC、IPC 与事件循环

**词条 ID：** `rpc-event-runtime`  
**词汇与别名：** RPC、IPC、event loop、callback、async future、消息  
**含义：** 调用、异步完成与共享执行资源的关系。

### 请求回包与关联 ID

调用端和服务端各有短执行轨道，请求记录与响应记录通过相反方向连接，使用相同 correlation ID；超时点在调用端标出，不把超时自动解释为服务端已停止。

### 就绪环与挂起任务

事件循环采用小环形调度路径，ready 任务在入口短队列，等待 I/O 的任务放在环外；完成事件把任务重新送回 ready。环仅表示循环机制，不意味着每个任务并行执行。

**必要边界：** 异步提交不等于并行计算；请求、返回值、状态更新和回调分别表示。

## 背压与流量控制

**词条 ID：** `backpressure`  
**词汇与别名：** backpressure、bounded queue、rate limit、credit、flow control  
**含义：** 慢消费者如何影响上游进入速率。

### 有界缓冲与反向信号

生产者与消费者之间放短缓冲列，上限明确；缓冲接近满时，一条独立反向控制线回到上游阀门。数据仍正向流动，控制线不要画成数据回传。

### 信用票与受控发送

接收端发出少量带数量含义的信用标记，上游只在有信用时发送消息；消费后信用沿另一条线补回。适合 credit-based 协议，不套用所有限流。

**参考与取舍：** 尚无专门原图。原创或通用构造候选；没有已绑定的专门原图。

**必要边界：** 背压、丢弃和重试不是同一种策略；缓冲必须有定义容量，不能只画越来越长的队列。

## IR、图重写与代码生成

**词条 ID：** `compiler-lowering`  
**词汇与别名：** IR、lowering、codegen、compiler、TVM、MLIR、Triton、XLA  
**含义：** 从高层计算表示到可执行实现的变化。

### 三种表示逐级展开

高层用小型算子图，中层用带轴的张量或循环块，低层用简短代码页与设备入口。每一级保留同一操作 ID 的关联，变换节点放在表示之间，不把所有表示画成相同文字框。

### 局部重写与外部边界保持

前后计算图使用相同输入输出端点，融合范围用轻括号圈出；内部节点减少或调度变化用对应关系说明。代码生成在后续路径，不能把融合直接画成更少数学运算。

**参考与取舍：** [S07](../references/sourcebook.md#s07)。借鉴数据节点与操作节点分形、图层和算子层分工；不照搬横向文字层堆叠。

**必要边界：** 图重写、循环调度与机器代码生成不同；编译流程不自动代表运行时先后。

## CUDA Graph 捕获与重放

**词条 ID：** `cuda-graph`  
**词汇与别名：** CUDA Graph、capture、instantiate、replay、launch overhead  
**含义：** 重复提交模式与设备依赖图的复用。

### 捕获窗口与图句柄

初次执行轨道用括号标出 capture 范围，范围内的 kernel 和依赖收为一个小 DAG；实例化后生成图句柄，后续每轮只由该句柄指向同一可执行图。CPU 准备步骤保留在外部。

### 多次 launch 与整图提交对照

相同 GPU 计算片段上下对齐，上方 CPU 逐个 launch，下方 CPU 提交一次 graph。只压缩确实减少的提交间隙，计算块保持身份，避免把多个 kernel 涂成一个融合 kernel。

**参考与取舍：** [S12](../references/sourcebook.md#s12)。官方文章为捕获、实例化、重放的语义依据；本条结构为原创描述。

**必要边界：** 图重放不等于算子融合或缓存输出；CPU 代码通常不随 GPU graph 自动重放。
