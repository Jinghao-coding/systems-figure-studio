## Agent／智能体

**主题：** Agent、LLM 应用、工作流、人机协同。
**别名：** agent、AI agent、角色智能体；planner、executor、reviewer 等是任务中的具体角色，不默认全部出现。
**简要含义：** 在当前系统里承担指定角色的执行实体。可只表示身份；说明内部机制时再展开相关结构。

### 画法 A：角色头像与短标签

**具体怎么画**

使用一个轮廓清晰的小型机器人头像，保留圆滑的外形、简洁面部和少量辨识性细节。
头像下方或旁侧放短角色名，不额外套一层宽大卡片。多角色沿任务关系排列，保持相同的头像比例和线条；
用小角标或一处强调色区分角色，文字负责准确说明职责。可保留少量增加亲和感的细节，
不加入大面积发光、夸张表情或抢占注意力的配件。

**适用与调整：** 角色总览、用户与 Agent 的交互、以协作关系为主的小型架构图。头像本身可构成完整组件。
**参考与取舍：** 原创候选；不宣称来自特定论文。图标形状是身份表示，不代表真实模型结构。
**误读提醒：** 只有当前系统存在多个实体才重复头像；不同时间的同一 Agent 保留身份。

### 画法 B：以状态与路径表示 Agent

**具体怎么画**

不使用头像，将任务中确实存在的状态与操作沿紧凑回路组织：输入在一侧进入，操作沿清楚路径展开，
反馈从下方回到对应接收位置。状态可用少量叠置的记录片，操作用小型节点，外部返回内容用一条短消息带。
让回路形态承担整体辨识，不强行用一个大矩形包住所有内容。线条以中性颜色为主，强调本图讨论的步骤。
实际没有循环时改为顺序或分支结构，不为画得像 Agent 而添加回路。

**适用与调整：** 解释给定 Agent 的状态变化或执行过程；只展开有依据的内容。
**参考与取舍：** 原创候选；其构造应由本次系统描述补足，不预设所有 Agent 都有记忆、规划或工具。
**误读提醒：** 回路中的先后关系不是模块包含关系；控制和返回数据在必要时区分。

### 画法 C：头像与局部结构组合

**具体怎么画**

保留小型 Agent 头像作为身份锚点，在一侧展开当前讨论的内部结构；头像面积不超过展开结构的视觉重量。
用细引线或明确的局部展开关系连接二者，不能画成两个独立执行实体。展开部分只包含已说明的状态或机制，
例如少量记忆条目与读写路径，或一组规划任务与后继关系。头像采用与结构同一色系，展开的焦点采用强调色；
远离焦点的细节折叠，保证小尺寸下仍能分清身份与机制。

**适用与调整：** 既要易于识别 Agent，又需要解释一项局部机制的架构图。
**参考与取舍：** 原创组合提案，不代表某篇论文的完整机制。
**误读提醒：** 用于局部展开的引线不表示新的数据请求；不要为了填满结构增加不存在的组件。

## 多 Agent 协作／Multi-agent collaboration

**主题：** Agent、工作流、人机协同。
**简要含义：** 多个具有不同身份或角色的参与者进行任务交接、消息交换或协作执行。
不默认采用中心协调器，不将所有工作流都画成全连接。

### 画法：角色图标与局部任务分支

**具体怎么画**

将同一图标家族的角色按真实任务关系排列，主协作路径保持易读的方向；在确有并行的地方用对齐分支展开。
角色旁只附必要任务或消息，不把每一条信息都套成独立卡片。存在人工审批时加入同风格人物头像和清楚的交接路径。
共同产物可放在实际汇合位置，使用一组简短文档页或结果片；边指向真实接收者，必要时标明任务、消息或反馈。
共享线条和配色规则，同时让每个角色具有稳定 ID。少量配件可增加趣味，但角色名仍需明确。

**适用与调整：** 以分工和交互为重点的总览；需要时间细节时另用执行泳道，不在头像周围塞满时间标记。
**参考与取舍：** 原创候选。未来可追加经实际审图的拓扑或角色排列参考。
**误读提醒：** 汇合是否等待所有前驱由真实机制决定；显示多个角色不等于存在多个独立模型实例。
