# Iteration from concrete feedback

| Feedback | Repair |
|---|---|
| Looks like a coursework flowchart | Replace generic text boxes with paper-defined objects and expose relationships at the correct level; preserve genuine serial flow |
| Too stiff / AI-template-like | Keep alignment but vary internal primitives and region dimensions by role; use small DAGs, tiles and model stacks |
| Too much whitespace | Fit frames to content, shorten detours, move related groups together; retain useful breathing room; allow small coherent details without treating every gap as a defect |
| Too many details in overview | Retain interfaces and key objects; move state transitions, formulae and decisions into module figures |
| Arrows indistinguishable | Inventory data/control/feedback and use explicit line/color/label mapping; distinguish candidate comparison from dispatch |
| Components not lively enough | Give them meaningful internal form: feature vector, request slots, model layers or branch frontier; a coherent role avatar is also valid when identity is the purpose |
| Need recognizable models | Add sparse truthful identifiers plus role labels; do not import brands from references |
| Only recolored; concrete objects still missing | Read the relevant component variants and change silhouette, parts, organization or interfaces; inspect whether the new structure actually explains the object |
| Old palette looked better | Compare what worked in the older palette with other suitable families; preserve useful contrast or softness while selecting the best overall composition, without automatically reverting or flattening objects into blue-gray boxes |
| Too much explanatory text | Keep object names and necessary technical labels; remove redundant editorial subtitles and let geometry express relationships |
| Logo feels pasted on | Attach an accurate mark to its actual platform, model, framework or interface; coordinate its size and connectors with the component |
| Good composition but wrong detail | Target related repairs, preserve layout, then recheck the full image |

## Stop propagation of errors

Inspect edits for changed labels, extra arrows, duplicated selected marks, altered identities, arithmetic and state changes. Two panels comparing a placement need the same candidate. A delayed non-critical branch must not be mislabeled originally critical. Completion frees a slot. A symbolic table must retain its paper-defined index and meaning.

If local edits repeatedly drift, return to the best accepted draft, simplify conflicting constraints or redraw the composition. Do not repeatedly regenerate one arrow indefinitely. Deliver an honest correction list if the tool cannot resolve it; the user may manually redraw. Offer native production only when requested, not as an automatic fallback.

## Example repair

A scheduling overview begins as four equal tall cards with prose labels. Retain the actual interfaces, open the workflow region into two small DAGs, place prediction above scheduling if they share inputs, and draw runtime endpoints as short model/slot groups. Route blue request/data, orange control, gray dashed feedback. Replace candidate arrows that look like feedback with neutral comparison marks. Keep the full state rail and decision arithmetic for separate mechanism views. The result gains concrete objects without importing new mechanisms.
